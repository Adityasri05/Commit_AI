# Weak Supervision with Labeling Functions

Weak supervision creates training labels from imperfect, incomplete, or noisy sources instead of requiring a human to label every example. It is useful when domain rules, existing databases, heuristics, knowledge bases, or distant supervision signals are available.

The key idea is to combine several imperfect labeling sources and estimate how to use them. Weak supervision is not the same as pretending noisy labels are ground truth.

## Sources of weak labels

- **Heuristics:** A rule labels messages containing a known phishing phrase as suspicious.
- **Existing systems:** A legacy classifier supplies provisional labels.
- **Distant supervision:** A knowledge base supplies labels based on known relations.
- **Crowd labels:** Multiple annotators provide noisy or conflicting judgments.
- **Pattern matchers:** Regular expressions identify likely entities or events.

Each source has a coverage and an error profile. A rule may be precise but apply to very few examples; another may cover many examples but make frequent mistakes.

## Labeling functions

A labeling function (LF) maps an example to a class or abstains when it has no useful opinion. For binary classification, one convention is:

- +1: positive
- -1: negative
- 0: abstain

A set of labeling functions creates a label matrix L with one row per example and one column per function. The matrix exposes agreement, conflict, and coverage.

~~~python
ABSTAIN = 0
SPAM = 1
NOT_SPAM = -1

def lf_has_urgent_link(message):
    text = message.lower()
    if "verify your account" in text and "http" in text:
        return SPAM
    return ABSTAIN

def lf_known_sender(message):
    if message.sender_domain in {"company.example", "school.example"}:
        return NOT_SPAM
    return ABSTAIN
~~~

The example is illustrative: production rules need domain review, safe parsing, and tests. A rule based on a sender domain can be wrong when messages are spoofed or compromised.

## Combining weak sources

A simple majority vote is an understandable baseline. More advanced label models estimate source accuracy and dependency patterns, then produce probabilistic labels.

Important concepts:

- **Coverage:** Fraction of examples on which a source does not abstain.
- **Conflict:** Fraction of examples receiving different non-abstaining labels.
- **Overlap:** Fraction receiving at least two non-abstaining labels.
- **Accuracy:** Agreement with trusted ground truth on an audit sample.
- **Correlation:** Two rules may share the same underlying assumption, so their agreement is not independent evidence.

A generative label model can help combine sources, but its assumptions matter. If several labeling functions are highly correlated and the model treats them as independent, confidence can become overstated.

## Recommended workflow

1. Define the target labels and the population to which the model will apply.
2. Write labeling functions with clear names and documented assumptions.
3. Measure coverage, conflict, overlap, and correlations.
4. Create a small, carefully reviewed gold evaluation set.
5. Fit a label model or compare with majority voting.
6. Inspect high-confidence and low-confidence examples.
7. Train the downstream model on probabilistic or filtered labels.
8. Evaluate only against trusted labels, never against the weak labels used for training.

## Common pitfalls

- **Circular validation:** Measuring model quality against labels generated by the same rules only measures rule imitation.
- **Hidden dependence:** Duplicate heuristics can dominate a label model.
- **Class imbalance:** Sources may label only common classes.
- **Rule drift:** A heuristic can become stale as language or business processes change.
- **Overconfidence:** A label model's probabilities are not automatically calibrated.
- **Abstain misuse:** A rule should abstain when it lacks evidence rather than forcing a guess.

Weak supervision reduces labeling cost, but it does not eliminate the need for trusted evaluation and human review.

## Mini-project

Build five labeling functions for a small sentiment or spam dataset. Compare majority-vote labels with a weak-supervision label model. Audit 100 examples against human labels and report coverage, conflict, class distribution, and downstream macro-F1 on a separate gold test set.
